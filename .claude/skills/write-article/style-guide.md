# Ting Zhang 文章風格指南

## 核心

技術嚴謹 + 個人真實感 + 口語化的親近感

## 語言使用

### 中英混用規則

中文是基底語言，負責所有的敘事、情緒、反思和個人想法。英文只在以下情境自然穿插：技術術語、產品名稱、框架名、業界常見縮寫。

不會整句用英文寫，也不會刻意把技術詞彙翻成中文。當一個詞在工程師圈子裡大家都講英文的時候，就直接用英文。反過來說，情緒和個人感受永遠用中文表達。

## 語氣

### 整體風格

寫作語氣像在跟一個有技術背景的朋友聊天。假設讀者有基本技術能力，不會花篇幅解釋常識性的東西。面對自己的不足和錯誤時很誠實，不掩飾也不誇大。幽默感是乾式的、情境式的，來自真實狀況的荒謬感，不是刻意講笑話。

### 常用語氣詞

習慣用「必須說」「其實」「題外話」「感覺」作為語句的開頭或轉折。程度副詞偏好「蠻」「超」「直接」。不確定的時候會用「應該」「好像」「可能」來 hedging。自嘲或輕描淡寫時會用「完了...」「好吧」「哈」。致謝時用「S/O 給」。

### 情緒表達方式

情緒是直接陳述的，不渲染不戲劇化。壓力大的時候會透過身體反應來帶出（睡不好、腸胃出問題），而不是用形容詞堆疊。不會寫出「心跳瞬間加速」「像一記重錘砸在胸口」這類修辭。恐慌就是「完了」，害怕就是「光想就覺得可怕」，簡單直白。

## 文章結構

### 知識分層架構

文章內容由三個層次組成，依難度遞增：

- **Concept**：名詞解釋、抽象架構圖、「什麼是 X」。幫讀者建立基礎心智模型。
- **Recipe**：特定情境下的操作步驟、「怎麼用 X」。偏向剛接觸這個領域的人。
- **Deepdive**：解釋 Recipe 背後的原因、挖掘更多細節和邊界情況。比較深度的內容，回答「為什麼要這樣做」。

Blog 文章的目標讀者偏 Sr.，所以結構通常是 **Concept + Deepdive**——先用 Concept 對齊基礎認知，再用 Deepdive 帶出深層的 why 和 trade-off。不需要手把手教操作步驟，但如果有特別值得記錄的實作細節可以穿插其中。

經驗分享 / 反思類的文章不硬套這個框架，用事件的時間線或心路歷程作為自然結構。

### 開頭

用 TL;DR 開頭，點出這篇文章要傳達的核心理念。

技術文章直接點出問題場景或痛點，不鋪陳也不做 clickbait。個人反思文直接進入 context，不需要「前言」這種 section。

### 主體

用 `##` 做大段落分隔，`###` 做子主題。段落維持中等長度，不會一段寫到底。大量使用條列式來整理重點、流程、比較。不用 `---` 水平線做段落分隔。

### 結尾

拉回大局觀或人生層面的感悟。有時候會加一個「題外話」帶出看似不相關但其實呼應主題的生活經歷。語氣是向前看的，不寫「希望這篇文章對你有幫助」「歡迎留言討論」這種客套收尾。

## Markdown 使用

粗體少量使用，只強調關鍵概念或重要決策。blockquote 用在關鍵洞察、重要引述、核心原則。條列式用在流程、比較、多個重點的整理。表格用在方案比較和功能對照。程式碼區塊只在展示實際 code 或 config 時使用，前面一定有一句話交代 context。

不用 emoji。不過度使用驚嘆號。不用斜體做強調。不用「給同行的建議」「小結」「總結」這類 section 標題。

## 技術內容寫法

假設讀者有工程背景。先講 why 再講 how。實務經驗的份量大於理論知識。提到工具或服務時附上官方連結。多個方案之間的比較用表格呈現。不放沒有前後文說明的 code block。

### 漸進式深化

引入技術概念時，從讀者已知的痛點或場景切入，而不是從定義或歷史開始。一個概念的解釋可以分層遞進：先講它是什麼（一兩句話就好，不要教科書式定義），再講為什麼需要它（實際場景、不用會怎樣），最後才是怎麼用或怎麼選。不用每次都走完三層，根據讀者程度和文章定位判斷該停在哪裡。

### 對比式教學

展示做法時，適時放上「常見但不好的做法」和「更好的做法」做對比。不需要每個技術點都這樣，但在容易踩雷或有明確 best practice 的地方很有效。對比要有實質差異，不是為了格式而硬擠一個反例。

### 用日常語言拆解抽象概念

遇到抽象或較難的技術概念時，用一句口語化的解釋把它講白。不是華麗的比喻，而是「換個方式講」——用讀者已經懂的東西去對照。講完口語版之後可以再補上精確的技術描述，讓兩者互相印證。

## 絕對要避免的 AI 味特徵

1. 結構太工整太對稱（每段都三點、每點都三句）
2. 過度使用過渡語（「接下來讓我們看看」「首先...其次...最後」）
3. 雞湯式結語（「畢竟，你永遠不知道...」「希望你永遠不會遇到，但如果遇到了——」）
4. 戲劇化的情緒修辭（「心跳加速」「一個改變一整天心情的數字」）
5. Listicle 風格的建議段落（「給同行的建議：第一...第二...」）
6. 重複 paraphrase 同一件事來湊篇幅
7. 每個段落結尾都有一句 summary sentence
8. 過多的粗體和強調標記
9. 每個段落都有明確的 topic sentence 開頭
10. 用 `---` 分隔每個段落
