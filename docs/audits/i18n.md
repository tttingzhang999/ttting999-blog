# i18n audit — 2026-10-19

## Findings

- `nav.projects` exists in all three catalogs. Its English value is `Projects`;
  the following dot is a separate span in the page heading.
- Scanned 51 Vue/TypeScript source files in pages, components, composables and
  layouts: all 134 static translation references (82 distinct keys) resolve in
  every locale. All messages compile and interpolate successfully.
- Catalog parity regression initially failed: `projects.featured` existed only
  in English. Added Traditional Chinese and Japanese translations. This key has
  no current source references and does not explain the reported heading failure.
- Each locale now contains the same 161 keys.
- The blog archive and articles intentionally have one Chinese content URL;
  their navigation language preference is separate. Hardcoded Chinese archive
  controls and article text are outside the localized home/resume/projects routes.
- The shared gallery uses English previous/next image accessibility labels in
  every locale. English pages are unaffected; this is a remaining localization
  gap for Chinese/Japanese gallery controls.

## Browser evidence

- Local production static output: three locales across home, resume and projects
  pass after hydration; headings and project details display translated text.
- Project headings, detail controls and chapter navigation are translated with
  JavaScript disabled in all three locales.
- Repeated zh-TW → en → ja → zh-TW → en navigation, resume/project navigation,
  mobile blog round trip, chapter anchors, and reading-position continuity pass.
- Live `https://info.tttingzhang999.com`: the original four browser scenarios pass
  (three localized page sweeps plus repeated locale/navigation changes).
- The user's already-open Dia tab at `/en/projects/` visibly displayed `Projects.`
  after loading. No refresh or navigation was performed to obtain that observation.

The reported `nav.projects.` rendering was not reproduced. No root cause or
translation-loader fix is claimed. Cache or intermittent network failure remains
an unverified hypothesis; this audit did not clear browser/CDN caches or deploy.

## Validation

- `npm test`: 29 pass; reported overall line coverage 99.25%.
- `npm run typecheck` using the project's Node 24: pass.
- Production static generation after catalog changes: pass (88 routes).
- Focused production browser suite: 12 pass, including 8 new audit scenarios and
  4 existing language-continuity scenarios.

New catalog regressions enforce parity, static-reference resolution and message
compilation. Browser regressions assert translated text rather than only route
